## 11. Display name and identity semantics

Date9ja’s `display_name` is the public member name (`first_name` is an API/model
alias for it). `full_name` is distinct and must not replace it on public
surfaces. The production shape supports that distinction: 567 display names are
one token and 17 are two tokens, while full names are 25 one-token, 539
two-token, and 20 three-or-more-token values.

The current D8N mapping is semantically correct on this point:

- `users.display_name` → brand `Profile.display_name` (public nickname/name);
- `users.full_name` → platform `User.first_name`/`last_name` parsing for private
  identity/account use;
- neither value is promoted into legal-name or verification evidence semantics.

The sanitizer pseudonymizes both, so exact production spelling/parsing must be
reconciled only in the controlled production-classified pass.

### Implementation pass 2 (2026-09-10)

The remaining historical domains now have concrete importers and per-entity

- **`MessageReaction`** is a new canonical, member-visible model (brand-scoped,

### Implementation pass 3 (2026-09-10) — review corrections

Defects raised against pass 2 are now fixed:

- **Verification losslessness.** `VerificationAssertion` gained a `source_id`
  column with a unique `(brand, source_type, source_id)` index, so every
  source check / event / legacy selfie row is its own assertion (no collapse on
  `(user, source_type, check_type)`). Each row is bound through
  `Migration::ReferenceMap` and its full source projection (reviewer id, tier,
  timestamps, evidence keys) is preserved under `metadata["source_row"]`.
- **Graph seed filtering.** `HistoricalGraphImport` takes
  `excluded_source_ids:` (auto-supplied by `HistoricalGraphSource#excluded_
  participant_ids`, i.e. `users.seed_account = true`). Any like / pass / match /
  message / block / report touching a seed account is skipped with reason
  `seed_linked_participant`. The 30 over-imported demo likes no longer import.
- **Complete country domain.** `CountryMapping` now backfills from
  `IsoCountryAliases::NAMES` — the full ISO 3166-1 name table plus common
  alternates — so a correctly-spelled country absent from the census still maps.
  Curated code aliases still win; typos / subdivisions (`california`, `nigeri`,
  `UAE`) stay deliberately unmapped.
- **Non-genotype V2 onboarding.** `SensitiveUserSource` now also selects
  `v2_onboarding_answers - 'genotype'`; `SensitiveProfileImport` preserves those
  flat answers verbatim into owner-only `Profile.metadata["date9ja_v2_
  onboarding"]` (gap-fill), with `v2_onboarding_answers_{mapped,preserved,
  absent}` reconciliation notes. Genotype keeps its separate gated destination.
- **Two-party history linkage.** Ledger rows for profile views, daily
  introductions, explore impressions, and tracked contacts now resolve the
  counterparty to its D8N `public_id` (`counterparty_ref` /
  `counterparty_migrated` in the payload) and every ledger row is
  `ReferenceMap`-bound by `(source_entity, source_id)`.
- **Trust-XP reconciliation.** `ExtendedHistoryImport` sums imported
  `trust_events.points` and the entitlement `trust_xp` snapshot and reports
  `trust_xp_delta` in the run metrics (expected 0; a non-zero delta is a
  finding).
- **Interaction gate is brand-scoped.** The history / conversation-read
  relaxation applies only to `brand.slug == "date9ja"`; DateZA keeps its uniform
  gate (regression fixed, `dateza_interaction_verification_test` green).

`db/schema.rb` is regenerated only after `db:migrate` succeeds locally; it is
part of the changeset because the additive migrations are.

Demonstrated blockers found on the rehearsal and fixed with tests:

- **Media messages were silently dropped.** Date9ja stores message media as an
  Active Storage attachment, not an inline column, so 22 image/video messages

  now joins the blob and emits a PII-free reference (`date9ja-blob:<id>` plus

  D8N `Report.reason` values — 3 of 5 dropped, the other 2 filed as `open`
  (phantom queue for resolved tickets). Now an exact decode
  (`inappropriate→inappropriate_content`, `scam→other` with the integer kept in
  `evidence.source_category`); `resolved_at` ⇒ `dismissed` with
  `evidence.source_resolution`. Rehearsal: 5/5, 0 open.
- **Extended-history schema drift.** The per-entity column config assumed names
  the v3 schema does not use (`explore_impressions.user_id`,
  `notifications.user_id`, `notification_deliveries` owner, `trust_events` kind,
  counterparty columns, etc.), silently dropping 35k+ rows under a false
  `owner_not_migrated` reason. Column maps corrected; new
  `ExtendedHistorySource::SchemaDrift` fails loud on a missing configured
  owner/counterparty column. Rehearsal: 45,658 imported, 0 failed.
- **`trust_xp_delta` false 5,000.** The points sum counted all events while the
  entitlement sum counted migrated users only. Points are now scoped to the
  migrated cohort; delta = 0.
- **`User#public_id` crash** in lifecycle moderation-state import — resolve the
  actor's brand `Profile` instead.
